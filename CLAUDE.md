# dotfiles

Neovim (LazyVim), lazygit and git/delta in One Dark Pro, installed by `install.sh` the same way
on macOS, Linux (x86/ARM) and WSL, including boxes without sudo. The README covers usage; this
file covers how it works and what to keep true when changing it.

## Layout

| Path | Role |
|---|---|
| `install.sh` | the installer; safe to re-run |
| `mise-global/` | symlinked as `~/.config/mise`: `config.toml` (tools + settings), `mise.lock`, `.mise/locks/` (npm dependency locks) |
| `mise-fallback/` | zig and 7-Zip, installed only when a box lacks cc/unzip and sudo |
| `scripts/pins.sh` | mise and Nerd Font versions + SHA-256s, generated by `scripts/update-pins.sh` |
| `scripts/keep-newer.sh` | used by `update.yml` to undo any bump that would go backwards |
| `scripts/lock.sh` | regenerates both mise lockfiles for linux/macos x64/arm64 |
| `scripts/verify.sh` + `verify-nvim.lua` | checks a finished install (tools, theme, parsers, LSP attach, formatters, codelldb) |
| `scripts/test-linux.sh [--no-sudo]` | install + verify + re-run + repo-clean check in a fresh Docker box |
| `nvim/` | LazyVim config, symlinked as `~/.config/nvim`; plugins pinned in `lazy-lock.json` |
| `lazygit/config.yml`, `git/delta.gitconfig` | linked / included by `install.sh` |
| `scripts/hooks/pre-commit` | gitleaks secret scan on staged changes |
| `.github/workflows/` | `ci.yml` (shellcheck, gitleaks, Linux sudo/no-sudo, macOS), `update.yml` (weekly bump PR) |

## Rules

- **Everything is pinned and checksum-verified.** Tools go in `mise-global/config.toml` at an
  exact version, then `scripts/lock.sh`; `locked = true` makes mise refuse anything not in the
  lockfile. Only `aqua:`, `github:`, `npm:` and core backends; `asdf`/`vfox` are disabled because
  they run arbitrary scripts. Downloads before mise exists go through `fetch` in `install.sh`
  with a pinned SHA-256 in `scripts/pins.sh`. Never add `curl | sh`.
- **No Mason.** LSP servers, formatters, linters and codelldb come from mise
  (`nvim/lua/plugins/mise-tools.lua` disables Mason). A new LazyVim extra that wants a Mason
  package needs that tool added to mise instead; `verify-nvim.lua` should check it.
- **No sudo unless allowed.** Only section 2 of `install.sh` may use sudo, and `--no-sudo`
  must skip it. Anything else installs under `$HOME`.
- **New configs** go in the repo and get a `link` line in `install.sh`; never write directly
  into `~/.config`. Shell startup lines go through `write_block`, not appends.
- **No secrets in the repo** (it's public). Machine-only settings go in
  `~/.config/dotfiles/local.sh`, which the shell blocks source; git identity stays in
  `~/.gitconfig`. gitleaks guards commits (hook in `scripts/hooks/`, enabled via
  `core.hooksPath`) and CI scans the full history.
- **Re-runs change nothing** and **installing never modifies the repo**; `test-linux.sh` and CI
  check both.
- Keep `install.sh` working in macOS's bash 3.2 (no `mapfile`, `${var,,}`, associative arrays)
  and shellcheck-clean.

## Testing

`scripts/test-linux.sh` and `scripts/test-linux.sh --no-sudo` before pushing changes to
`install.sh`, the mise config or the Neovim tool setup (a few minutes each; the checkout is used
as on disk but the repo-clean check compares against HEAD, so commit first). macOS is only
covered by CI. Don't test on the user's machine: `~/.config/nvim` is a live symlink into
`~/dotfiles`, so edit and test in a separate clone.

## Non-obvious things learned the hard way

- A `mise/config.toml` inside a repo counts as that repo's project config, which is why the
  folder is `mise-global/`, not `mise/`.
- `scripts/lock.sh` locks through a temporary `XDG_CONFIG_HOME` so the lock is written the way a
  real machine reads it (global config).
- A fresh `Lazy! restore` doesn't fully honour `lazy-lock.json`: plugins that only appear after
  LazyVim itself is installed are cloned at their latest commit and written back over the pin.
  It only shows once those plugins get new upstream commits, so CI can pass one day and fail the
  next. `install.sh` saves the lockfile, installs, puts it back and restores again.
- mason-lspconfig skips `ensure_installed` when headless; one reason Mason was dropped.
- zig can't parse the Rust-style `-target aarch64-unknown-linux-gnu` that tree-sitter passes;
  the `cc` wrapper drops it.
- Tools only call `unzip [-o] -d DIR FILE`, so 7-Zip can stand in.
- lazygit's `{{columnWidth}}` is half the panel width minus 6 (meant for ydiff); delta wants the
  full width, hence `$(( ({{columnWidth}} + 6) * 2 ))`, which works because lazygit runs pagers
  via `sh -c`.
- `mise upgrade --bump` keeps version precision but takes Node to the newest release overall;
  `update.yml` bumps Node separately via `node@lts` with `MISE_PIN=true`.
- The 7-day minimum release age can pick a release *older* than one already pinned (a pin newer
  than a week); `scripts/keep-newer.sh` and a check in `update-pins.sh` stop updates going
  backwards.
- Pushes made with the workflow token don't trigger workflows, so `update.yml` starts CI with
  `gh workflow run`.
- Ubuntu's `~/.bashrc` returns early for non-interactive shells; verify in `bash -lic`.
